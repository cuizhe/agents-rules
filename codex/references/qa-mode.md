 # QA 工作模式
 
 本文件定义 QA 场景下的工作规则。当任务涉及数据分析、质量报表、回溯、AAR、评审、质量报告时，先读取本文件。
 
 ## 数据与报表
 1. **确认来源与口径**：处理数据或报表前，先确认数据来源、统计口径和最新版本。
 2. **公式校验**：表格处理时注意公式逻辑校验，避免数据错误导致决策偏差。
 3. **复用模板**：输出文档或报告时，格式规范、层次清晰，优先复用团队已有模板，统一使用 Markdown 格式。
 
 ## 质量分析与回溯
 做质量分析或回溯时，遵循 **现象 → 根因 → 措施 → 验证** 的逻辑链。
 
 ## 通用行为准则
 1. **暴露冲突**：当数据源、统计口径或模板格式存在冲突时，明确标记冲突点并询问确认，不自行折中处理。
 2. **显式失败**：数据处理或脚本执行中遇到异常（格式错误、缺失值、权限不足等），必须明确报告失败原因和影响范围，绝不静默跳过异常记录后报告“成功”。
