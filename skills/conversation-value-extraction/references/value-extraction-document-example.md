# 会话价值提炼文档示例

> 来源：用户实际会话的脱敏处理后提炼结果
> 用途：展示信息密度、结构格式和粒度标准

---

## 价值提炼示例（真实会话）

### 1. 下次可以直接用的方法或提示词

- 使用 `skill-creator` 的 `evals/evals.json` 结构做回归测试，每次修改后跑一遍确保不退化
- 写 skill 描述时把 `MUST` 换成 `why`（用"宁缺毋滥"替代"不要硬凑"），模型理解更自然
- 技能触发判断不需要写复杂的逻辑分支，直接按用户意图最明显的那个走

### 2. 值得记下来的知识点

- Kimi 的 skill 不支持热重载，只有新会话启动时才加载 `.kimi-code/skills/`
- `compatibility` 字段在 `skill-creator` 规范中标注为"可选，很少需要"，无特殊依赖应直接删除
- 文件名精确到分钟（`{HHMM}`）时，"重名覆盖确认"规则基本冗余

### 3. 值得继续探索的方向

- 批量迁移 Claude 的 `.claude/skills/` 到 Kimi 的 `skill` 格式，是否需要统一转换脚本
- 技能拆分后如何避免两个 skill 在模糊表达时竞争触发（比如"整理一下"）

### 4. 我自己说过的判断或倾向

- 拆分 skill 比合并更好，单一职责更干净
- 错误处理后置到文档末尾，避免前置占用核心上下文
- 不需要保留旧版本的备份文件，直接覆盖即可

---

## 输出要求

- 用清单格式，每条一句话，不展开解释
- 每个方向最多 3 条，宁缺毋滥
- 不引入对话外的信息
- 文档末尾无特殊提示（价值提炼不需要"复制到新对话"这类提示）
