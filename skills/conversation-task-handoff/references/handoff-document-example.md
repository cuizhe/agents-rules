# 会话任务迁移文档模板示例

> 来源：用户实际使用的迁移文档（已脱敏处理）  
> 用途：当任务迁移模式被触发时，参考此示例的结构密度和信息粒度来生成迁移文档。

---

## 标准结构

### 1. 任务概述
用 1-2 句话说清：本次会话涉及哪些并行事项、各自处于什么状态、有无单一未完成的主线任务。

### 2. 必要背景
分为固定背景（用户身份、职业、技术环境偏好）和会话特定背景。

固定背景示例：
- **用户身份**：国内软件外包公司 QA 质量专员，非程序员
- **核心工作**：交付管理类平台支撑 + 项目质量管理（42+ 项目）
- **工作沟通风格**：简洁、直接、言简意贴
- **技术环境**：WSL2，Hermes Agent 已安装，opencode CLI 在 `~/.opencode/`
- **更新偏好**：Hermes 版本按月周期更新，不追新
- **渠道限制**：飞书交互按钮有 bug，敏感操作需文字确认

### 3. 已完成的内容
用表格列出具体产出物、路径、状态。避免"已完成第一步"等空话。

示例：
| 产出 | 路径/状态 |
|---|---|
| WebUI 安装启动 | `~/.hermes/hermes-webui`，进程活跃，端口 8787 |
| Skill 已创建 | `~/.hermes/skills/productivity/...` |
| 用户写作风格已写入记忆 | 随笔/工作沟通分场景 |

### 4. 下一步行动
分三层：
- **立即要做的**：无立即待办事项（所有事项已闭环或稳定运行）
- **后续步骤**（按需触发）：列出可能的后续动作及触发条件
- **注意事项**：飞书 gateway 按钮 bug、WebUI 无密码、版本更新节奏等

---

## 输出要求
- 用 Markdown 格式，结构清晰便于复制
- 文档末尾单独一行提示：**以上内容可直接复制粘贴到新对话开头使用**
- 信息密度优先，不写废话、不写过渡句
