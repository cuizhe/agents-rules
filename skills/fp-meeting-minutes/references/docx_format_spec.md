# 会议纪要 Word 文档格式规范

本文档集中定义会议纪要生成过程中所有 Word 格式参数。被 `scripts/generate_minutes.py` 脚本读取并应用。

---

## 通用字体规范

| 属性 | 值 | 说明 |
|------|-----|------|
| 中文字体 | 微软雅黑 | `w:ascii`、`w:hAnsi`、`w:eastAsia` 三个属性必须同时设置 |
| 西文字体 | 微软雅黑 | 与中文保持一致 |
| 正文字号 | 五号 = 10.5pt = 21 half-points | `w:sz="21"`、`w:szCs="21"` |
| 标题字号 | 2号 = 22pt = 44 half-points | 仅主标题使用 |

> ⚠️ **字体陷阱**：仅设置 python-docx 的 `run.font.name` 只会写入 `w:ascii` 和 `w:hAnsi`，不会写入 `w:eastAsia`。Word 显示中文时会回退到宋体。必须通过 XML 操作或 `rFonts` 元素显式设置三个属性。

---

## 段落缩进规范

所有段落（包括正文段落和表格单元格内的段落）必须显式覆盖 `Normal` 样式的首行缩进：

- `paragraph_format.first_line_indent = 0`
- `paragraph_format.left_indent = 0`

> ⚠️ `w:firstLine="0"` 与 `w:firstLineChars` 是 OpenXML 中两个独立属性。`Normal` 样式可能通过 `w:firstLineChars="200"` 定义缩进（约2字符），仅设置 `first_line_indent = 0` 无法覆盖。必须同时移除或覆盖 `firstLineChars`。

---

## 表格通用规范

### 单元格边距清零

Word 表格默认在表格级别（`tblCellMar`）和单元格级别（`tcMar`）都带有内边距（左右约 0.19cm）。生成时必须同时清零两个层级：

- **表格级别**：`tblCellMar` 的 `top`、`left`、`bottom`、`right` 全部设为 `0`
- **单元格级别**：每个单元格 `tcMar` 的 `top`、`left`、`bottom`、`right` 全部设为 `0`

确保页面视图下内容紧贴单元格边框，不出现视觉上的"缩进"。

### 边框

所有表格统一使用单线边框：
- 粗细：4 eighth-points（0.5pt）
- 颜色：`000000`
- 范围：`top`、`left`、`bottom`、`right`、`insideH`、`insideV`

## FP 项目排产评审格式

### 标题

- 主标题：`会议纪要`（居中、加粗、2号）
- 副标题：`会议纪要    ☐外部会议 ☑内部会议`（左对齐、五号）

### 会议信息表（4列）

共5行4列：

| 行 | 第1列 | 第2列 | 第3列 | 第4列 | 合并说明 |
|---|-------|-------|-------|-------|---------|
| 0 | 会议名称 | 2026年X月FP项目排产评审会 | (合并) | (合并) | 第2-4列合并 |
| 1 | 会议类别 | ☐重大会议 ☑评审会 ☐例会 | (合并) | (合并) | 第2-4列合并 |
| 2 | 会议地点 | welink线上会议 | 会议时间 | 2026-X-X XX:XX~XX:XX | 不合并 |
| 3 | 参会人员 | 沙建银、崔哲、... | (合并) | (合并) | 第2-4列合并 |
| 4 | 纪要整理 | 崔哲 | 纪要审核 | 汪秀娟 | 不合并 |

#### 列宽

| 列 | 宽度 (DXA) | 说明 |
|---|-----------|------|
| 1 | 2000 | 标签列 |
| 2 | 3000 | 内容列 |
| 3 | 2000 | 标签列 |
| 4 | 3000 | 内容列 |

#### 行高

- 固定 **460 DXA**
- `hRule="atLeast"`（最小值模式），单行均匀，多行自动扩展

### 项目汇报格式

使用加粗正文段落（非 Heading 样式）：

```
1. 深圳移动-2026年-深圳民政局政务服务能力提升项目（PM：孟钊磊）
（1）项目进展：项目体量较大，排产计划细致...
（2）人员情况：团队规模9人...
（3）成本与毛利：按目前投入预估毛利约30%左右。
```

### 遗留事项表（3列）

表头行 + N 个数据行，**同一项目合并到一行**：

| 列 | 表头 | 说明 |
|---|------|------|
| 0 | 项目 | 项目名称 |
| 1 | 遗留问题/待办事项 | 详细描述 |
| 2 | 责任人 | 明确到个人 |

#### 列宽

| 列 | 宽度 (DXA) |
|---|-----------|
| 0（项目） | 1600 |
| 1（遗留事项） | 6400 |
| 2（责任人） | 900 |

#### 内容详实性要求

每条事项应包含：**具体动作** + **关键背景数据**（金额、人数、时间节点） + **当前状态/风险点**

## 解决方案业务月度管理格式

### 标题

两行居中标题（加粗、16pt）：

```
电信与AIoT业务线
解决方案项目月度管理会议纪要
```

### 会议信息表（2列）

共7行2列：

| 行 | 第1列 | 第2列 |
|---|-------|-------|
| 0 | 主题 | 2026年X月解决方案业务月度管理会议 |
| 1 | 时间 | 2026年X月X日（周X）XX:XX-XX:XX |
| 2 | 会议方式 | Welink语音会 |
| 3 | 召集人 | 沙建银 |
| 4 | 纪要整理 | 崔哲 |
| 5 | 与会人 | 沙建银、崔哲、... |
| 6 | 议题 | 工作事项与管理要求说明\n项目进展、风险及问题汇报 |

#### 列宽

| 列 | 宽度 (DXA) | 说明 |
|---|-----------|------|
| 1 | 2000 | 标签列 |
| 2 | 8000 | 内容列 |

### 重点事项与管理要求说明

章节标题（加粗、12pt），内容使用 `▸` 要点格式：

```
▸ 7月份工时严重不足，要求各项目经理及时完成签单填报...
▸ 开标回款从下周开始重点抓，现金流紧张...
```

### 项目汇报格式

项目标题（加粗、11pt），内容使用 `▸` 要点格式：

```
【丁召海】农业项目群（9个执行项目+5个客户线索）
▸ 目前在执行9个项目，5个客户线索。6月份AS系统填报收入20.6万元...
▸ 牧数查（二期）：截至6月底主体开发基本完成...
```

### 遗留事项表（7列）

表头行 + N 个数据行，**每行独立**（不合并）：

| 列 | 表头 | 说明 |
|---|------|------|
| 0 | 序号 | 1、2、3... |
| 1 | 问题/事项 | 详细描述 |
| 2 | 责任人 | 明确到个人 |
| 3 | 预计闭环时间 | 如 2026.07.31 |
| 4 | 实际闭环时间 | 如 / 或 2026.07.15 |
| 5 | 当前状态 | 进行中/待执行/已执行/待定 |
| 6 | 当前进展 | 具体进展描述 |

#### 列宽

| 列 | 宽度 (DXA) | 说明 |
|---|-----------|------|
| 0（序号） | 700 | 2-3个字符 |
| 1（问题/事项） | 3300 | 占主要空间 |
| 2（责任人） | 1100 | 约5-6个汉字 |
| 3（预计闭环） | 1100 | 日期格式 |
| 4（实际闭环） | 1100 | 日期格式 |
| 5（当前状态） | 900 | 3-4个汉字 |
| 6（当前进展） | 1700 | 进展描述 |

#### 内容详实性要求

遗留问题/待办事项的描述必须足够详细，每条事项应包含：
1. **具体动作**：谁要做什么
2. **关键背景数据**：金额、人数、时间节点等
3. **当前状态/风险点**：为什么这件事重要
