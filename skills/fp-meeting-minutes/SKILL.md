# 会议纪要生成助手

从会议口水稿（图片或文本）生成标准格式的会议纪要文档。

## 内置资源

### 模板文件

| 会议类型 | 模板路径 |
|---------|---------|
| FP项目排产计划评审会 | `assets/templates/FP项目排产评审会议模板.docx` |
| 解决方案业务月度管理会议 | `assets/templates/解决方案业务月度管理会议模板.docx` |

### 参考文献（按需读取）

| 文件 | 路径 | 何时读取 |
|-----|------|---------|
| 详细对话模板 | `references/workflow_dialogues.md` | 需要与用户确认会议类型、日期、口水稿来源时 |
| 项目名称清单 | `references/FP项目名称清单模板.xlsx` | **第四步** 解析口水稿前（强制） |
| Word格式规范 | `references/docx_format_spec.md` | 需要调整格式参数时 |

### 生成脚本

| 脚本 | 路径 | 用途 |
|-----|------|------|
| 纪要生成器 | `scripts/generate_minutes.py` | 从结构化数据生成格式规范的 Word 文档。支持 FP 和解决方案两种会议类型。 |
| 名称规范化 | `scripts/normalize_names.py` | 读取 Excel 项目清单，构建关键词索引，对口水稿执行名称规范化替换。 |
| 格式修复 | `scripts/fix_docx_format.py` | 修复已生成文档中的标题格式、表格缩进和边距问题。 |
| 输出验证 | `scripts/verify_output.py` | 检查生成的 docx 是否符合格式规范（3列遗留事项、项目合并、无缩进等）。 |
| 精校校对 | `scripts/proofread_minutes.py` | 对生成的 docx 做全面校对，检查错别字、语句不通顺、语音转译错误，输出 Markdown 校对报告。 |
| 公共工具 | `scripts/shared_utils.py` | 封装所有底层 OpenXML 操作（字体、缩进、边距、边框、垂直居中等）。被以上脚本复用。 |

## 工作流程

### 第一步：确定会议类型

询问用户会议类型（1. FP项目排产评审 / 2. 解决方案业务月度管理 / 3. 自定义），并记录对应模板路径。

> 详细的对话格式参考 `references/workflow_dialogues.md` 第一步。

### 第二步：确认输出信息

询问用户：会议日期、输出目录（默认为当前目录）。如为 **排产评审**，额外询问是否生成 AI 使用情况报告。

> 详细的对话格式参考 `references/workflow_dialogues.md` 第二步。

### 第三步：确认口水稿来源并读取

收集图片路径、文本内容或 docx 路径，提取纯文本口水稿。

> 详细的对话格式参考 `references/workflow_dialogues.md` 第三步。

### 第四步：加载项目名称清单并构建关键词索引（强制前置）

**⚠️ 必须先执行，再解析口水稿。**

1. 读取 `references/FP项目名称清单模板.xlsx`，提取"项目经理姓名"→"完整项目名称"映射
2. 构建关键词索引：项目经理姓名、完整项目名称、项目别名/简称（如"鼎桥"、"ICP"、"H5"等）

> **可直接调用**：`python scripts/normalize_names.py <excel_path> <transcript_path> [output_path]`
> 详细规则参考 `references/workflow_dialogues.md` 第四步。

### 第五步：预处理口水稿（名称规范化）

**⚠️ 必须先执行，再提取结构化内容。**

将关键词索引应用于口水稿全文，执行：
- 语音识别错误修正（如"SS桥"→"鼎桥ICP"）
- 口语化名称规范化（如"民政项目"→"深圳民政局政务服务能力提升项目"）
- 项目经理姓名关联（根据上下文判断 PM 所指项目）

匹配优先级：项目经理姓名 → 项目关键词/简称 → 完整项目名称。无法匹配时保留原文并标注"（未在清单中）"。

> **可直接调用**：`python scripts/normalize_names.py <excel_path> <transcript_path> [output_path]`
> 详细规则参考 `references/workflow_dialogues.md` 第五步。

### 第六步：从规范化后的口水稿中提取结构化内容

提取以下信息：
1. 会议信息、参会人员
2. 按项目归类的评审事项/进展及风险
3. 遗留事项（含责任人、预计闭环时间、当前状态、当前进展）
4. 决策事项
5. AI应用进展（仅排产评审，可选）
6. **重点事项与管理要求说明**（会议主持人或高层领导的管理要求/工作指示，作为独立章节，不可遗漏）

### 第七步：生成会议纪要（含待办跟踪）

**核心方式：调用内置生成脚本。**

1. **准备结构化数据**（Python dict / JSON），结构如下：
   ```python
   {
       "meeting_title": "2026年6月FP项目排产评审会",
       "meeting_type_badge": "☐重大会议 ☑评审会 ☐例会",
       "meeting_location": "welink线上会议",
       "meeting_time": "2026-6-5 10:08~11:33",
       "attendees": "沙建银、崔哲、...",
       "recorder": "崔哲",
       "reviewer": "汪秀娟",
       "leadership": ["▸ 7月份工时严重不足..."],  # 解决方案业务会议：重点事项与管理要求说明
       "projects": [
           {
               "pm": "丁召海",
               "name": "农业项目群（9个执行项目+5个客户线索）",
               "items": ["▸ 目前在执行9个项目...", "▸ 牧数查（二期）..."]
           },
           ...
       ],
       "todos": [
           {"no": "1", "detail": "...", "owner": "丁召海", "eta": "2026.07.31", "closed": "/", "status": "进行中", "progress": "..."},
           ...
       ],
       "highlights": [
           "1. 成本管控与生存压力：...",
           ...
       ]
   }
   ```

2. **调用生成脚本**：
   ```python
   import sys
   sys.path.insert(0, "<skill-path>/scripts")
   from generate_minutes import generate_fp_minutes, generate_solution_minutes
   
   # FP 项目排产评审
   generate_fp_minutes(data, output_path)
   
   # 解决方案业务月度管理
   generate_solution_minutes(data, output_path)
   ```

   脚本自动处理所有格式细节（表格合并、列宽、行高、字体、边距、垂直居中、项目合并等）。格式参数遵循 `references/docx_format_spec.md`。

3. **遗留事项内容质量检查**（在传入脚本前完成）：
   - 描述是否足够详细？每条事项应包含：**具体动作** + **关键背景数据**（金额、人数、时间节点） + **当前状态/风险点**
   - 责任人是否唯一且明确？
   - 预计闭环时间是否可执行？（避免周末或节假日）
   - 如有"待定"项，在表格下方备注原因和预计确认时间

4. **生成文档命名**：
   - FP项目：`【会议纪要】{年月}FP项目审视会议纪要-电信与AIoT业务线.docx`
   - 解决方案业务：`【会议纪要】{年月}解决方案业务月度管理会议纪要.docx`
   - 自定义文件名：由用户指定或自动生成

5. **格式验证（可选但推荐）**：
   ```bash
   python scripts/verify_output.py <output.docx> [--type fp|solution]
   ```

**备选方式（复杂模板场景）**：
如果用户提供了自定义模板且结构复杂，可调用 `minimax-docx` skill 进行模板套用。标准会议纪要优先使用 `scripts/generate_minutes.py`。

### 第八步：精校会议纪要（必做）

**对生成的 docx 文件做全面校对，输出校对报告供用户确认。**

1. **调用精校脚本**：
   ```bash
   python scripts/proofread_minutes.py <output.docx> -o proofread_report.md
   ```

2. **精校覆盖范围**：
   - **错别字/用词错误**：如"前项"→"前期"、"报到"→"达到"、"蜀回"→"签回"等
   - **重复表述**：相邻重复词或句子（如"签完后马上能签"）
   - **语音转译错误**：同音/近音字错误（如"起作业"→"启动作业"、"排进"→"排上"）
   - **缺少主语**：如"需进一步提供新数据"→"需客户进一步提供新数据"
   - **口语化表达**：如"搞"、"甩"、"给到"、"那边"等，根据正式程度建议优化
   - **金额/日期一致性**：同一项目中出现不同金额或日期矛盾
   - **标点符号**：中英文标点混用

3. **报告结构**：
   - **一、明显错误**（error）：建议必须修正
   - **二、建议优化**（warning）：根据正式程度决定是否调整
   - **三、存在疑问**（question）：需结合原始会议记录人工确认

4. **确认修正流程**：
   - 将校对报告呈现给用户
   - 用户逐项确认或提出异议
   - 根据确认结果统一修正 docx 文件（通过 `scripts/fix_docx_format.py` 或手动编辑）
   - 修正后再次运行精校脚本，确认问题已清零

> **精校报告仅作为辅助，最终内容以会议原始记录为准。** 行业术语（如"拉通"、"对齐"）在内部文档中可保留，但会标注为建议优化。

### 第九步：生成AI使用情况报告（可选）

**仅当用户在第二步中明确要求生成时执行。**

- 会议类型为 **FP项目排产评审**，用户回答 **y/是/需要**
- 生成文件：`项目{年月}使用AI情况.md`
- 格式：表格（项目名称、AI工具使用情况、进展描述）
- 数据来源：从口水稿中提取提及AI工具（Cursor、GPT、通义千问等）的项目信息

## 注意事项

1. **模板选择**：优先使用内置生成脚本，特殊需求支持自定义模板
2. **文件命名**：遵循上述命名规范，避免手动随意命名
3. **信息提取**：口水稿包含口语化表达，需提炼为正式文档语言
4. **项目名称规范**：必须参照 `references/FP项目名称清单模板.xlsx` 中的完整名称进行规范化，模糊表述通过清单检索后替换
5. **待办跟踪**：排产评审遗留事项以3列表格嵌入 Word 文档（同一项目多条待办合并到1行）；解决方案业务遗留事项以7列表格嵌入（序号/问题/责任人/预计闭环/实际闭环/状态/进展，每行独立）
6. **AI使用报告**：默认不生成，仅在用户明确请求且会议类型为 **排产评审** 时生成
7. **会议类型结构差异**（两种模板格式完全不同，不可混用）：
   - **FP项目排产评审会**：4列会议信息表 + 项目汇报（`1. 项目名（PM：xxx）` + `（1）...` 格式） + 3列遗留事项跟踪清单（无重点事项章节，有整体关注点）
   - **解决方案业务月度管理会议**：2列会议信息表 + 重点事项与管理要求说明（`▸` 格式） + 项目汇报（`【PM】项目名` + `▸` 格式） + 7列遗留事项跟踪清单（序号/问题/责任人/预计闭环/实际闭环/状态/进展）
8. **格式规范集中管理**：所有 Word 格式参数统一维护在 `references/docx_format_spec.md` 中，`scripts/generate_minutes.py` 和 `scripts/shared_utils.py` 自动应用。如需调整格式，优先修改格式规范文件和脚本，不要在 SKILL.md 中重复定义。
9. **依赖检查**：运行脚本前确认已安装 `python-docx`、`openpyxl`、`lxml`。如缺失，提示用户安装。
10. **精校环节**：生成 docx 后**必须执行**精校脚本，检查错别字、语句不通顺、语音转译错误。精校报告分三级（明显错误/建议优化/存在疑问），用户确认后再统一修正。精校脚本的规则库可扩展，维护在 `scripts/proofread_minutes.py` 中。
